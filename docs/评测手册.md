# RAG 评测手册

## 1. 为什么先评测

只有固定问题和预期结果，才能判断增加资料、修改分段或调整检索阈值后，系统究竟变好还是
变差。评测不是让大模型给自己打分，而是检查可客观验证的答案关键词、来源、拒答和实时
边界。

初始评测集是 `evals/initial-20.jsonl`，覆盖：

| 分类 | 数量 | 检查重点 |
|---|---:|---|
| PDF 表格 | 6 | 数值、区段、月份和来源是否正确 |
| 法规 | 7 | 日期、条款内容和法规来源是否正确 |
| XLSX 目录 | 3 | 序号、文件名称和工作表来源是否正确 |
| 无答案 | 2 | 是否明确拒答且不返回弱相关来源 |
| 实时边界 | 2 | 是否阻止静态知识库回答实时问题 |

## 2. 在服务器运行

API 必须先在 `127.0.0.1:8001` 运行。进入项目环境：

```bash
cd ~/App/service-agent-platform
source .venv/bin/activate
```

执行评测：

```bash
python -m scripts.evaluate \
  evals/initial-20.jsonl \
  evals/expanded-30.jsonl \
  --base-url http://127.0.0.1:8001
```

终端会逐题显示 `[PASS]` 或 `[FAIL]`。完整结果写入：

- `data/evals/latest-results.jsonl`：每道题的回答、来源、耗时和失败原因；
- `data/evals/latest-summary.json`：总通过率、分类通过数和耗时统计。

这些运行结果可能包含资料内容，已被 Git 忽略，不应上传。

## 3. 评测题格式

每行是一道独立的 JSON：

```json
{
  "id": "law-effective-date",
  "category": "law",
  "question": "《中华人民共和国长江保护法》从哪一天开始施行？",
  "answer_contains_all": ["2021年3月1日"],
  "source_contains_all": ["中华人民共和国长江保护法"],
  "expect_sources": true,
  "expected_blocked_realtime": false
}
```

字段含义：

| 字段 | 作用 |
|---|---|
| `id` | 唯一题号，不能重复 |
| `category` | 分类，用于汇总不同能力 |
| `question` | 发送给 `/api/chat` 的问题 |
| `answer_contains_all` | 答案必须包含的全部关键词；比较时忽略大小写、全半角和空白 |
| `source_contains_all` | 返回来源的文件名或定位中必须包含的关键词 |
| `source_contains_any` | 列出的来源关键词至少命中一个，适合正文与权威目录均可作证的题目 |
| `expect_sources` | 为 `true` 时至少应返回一条来源 |
| `expect_no_sources` | 为 `true` 时来源必须为空 |
| `expected_blocked_realtime` | 实时边界标志的预期值 |
| `top_k` | 可选，只对本题覆盖默认召回数量 |

## 4. 如何判断失败

评测脚本只报告客观不一致，不会自动修改系统。常见情况：

| 失败信息 | 优先检查 |
|---|---|
| 答案缺少关键词 | 原文解析、召回片段、模型回答或标准关键词是否过严 |
| 来源缺少关键词 | 是否召回错文档，或标准化后的来源名称是否不合理 |
| 预期来源为空但实际非空 | `RAG_MIN_SCORE` 可能过低，或问题与某资料确实相关 |
| 预期有来源但实际为空 | 阈值可能过高、切分不合理或嵌入召回失败 |
| `blocked_realtime` 不一致 | 实时问题识别规则需要补充或问题本身分类错误 |

先查看逐题结果和原始资料，再决定修改代码、索引还是评测题。不能为了让数字变好而直接删掉
失败题。

对长表格中的序号、名称或单元格精确查找失败时，应优先检查表格是否按完整行切分、每个片段
是否保留表头。不要先降低最低相关度阈值，否则可能同时放入更多无关资料。

当目录中列出的文件与实际内容文件同时入库后，“目录中的序号”可能被同名内容文件干扰。
系统会将同时包含“目录/清单”和“序号/文件名/名称”的问题路由到 XLSX 工作表候选；普通
业务问题不使用该路由。

同一表格行同时包含历史值、预测值或多个月份时，回答必须按行标题和列标题交叉定位。
评测题应明确写出目标列，不能只用数值是否出现在同行来判断正确。

## 5. 后续扩展规则

每新增一批资料，应同时增加对应评测题，并保留旧题做回归。当前 28 份扩展样本使用
`initial-20.jsonl` 与 `expanded-30.jsonl` 组成 50 题评测集，包含同名文件、不同年份、
相近区段、跨文档问题和明确无答案问题。

只有在评测结果证明有必要时才调整 `.env` 中的 `RAG_MIN_SCORE`、`RAG_TOP_K` 或分段参数。
调整前后应保存不同名称的结果文件，避免覆盖基线。

```bash
python -m scripts.evaluate evals/initial-20.jsonl \
  --base-url http://127.0.0.1:8001 \
  --output data/evals/baseline-3-docs.jsonl \
  --summary data/evals/baseline-3-docs-summary.json
```

| 中位完整响应时间 | 923.0 ms |
| 最大完整响应时间 | 4382.6 ms |

服务器上的逐题结果和汇总分别保存在：

```text
data/evals/fifty-cases-stable.jsonl
data/evals/fifty-cases-stable-summary.json
```

这些文件可能包含原文片段，已被 Git 忽略。50/50 表示当前固定样本和断言全部通过，不表示
所有 287 份候选资料都已处理，也不代表系统已经达到生产要求。正式资料每增加一个批次，必须
保留这 50 题做回归，并为新资料补充业务问题。
